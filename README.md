## 一、这个目录是什么

本目录是《基于大模型的骑行功率训练系统的设计与实现》毕业设计项目中，**全部功能模块与整体设计**的落地目录，覆盖三层架构的完整实现。目录名沿用了建立时的"骑行可视化与大模型"，不再表示范围限定。后续的新代码、脚本与阶段产出物统一放在这里，不再散落在 `Desktop\毕业设计` 根目录。

项目级的总体设计、决策与排期不写在本目录，仍以根目录的 [PROJECT_CONTEXT.md](../PROJECT_CONTEXT.md) 为唯一事实来源。本目录承载的是设计落地的代码与阶段产出物。

## 二、工作范围

范围与 [PROJECT_CONTEXT.md](../PROJECT_CONTEXT.md) 第五节的模块划分、第九节的开发批次一一对应：表现层 3 个模块、业务逻辑层 6 个模块、数据访问层 3 个模块，共 12 个功能模块。

| 层 | 模块 | 内容 | 对应决策 |
|---|---|---|---|
| 数据访问层 | 格式解析 | FIT、GPX、TCX 读取，逐条记录提取，活动摘要汇总 | D6 |
| 数据访问层 | 交叉验证 | 与 Garmin Connect 页面及文件 session 字段对拍 | P2 |
| 数据访问层 | 持久化 | 原始文件归档、活动与每秒数据入库、查询接口 | D10、6.6、6.7 |
| 业务逻辑层 · 领域计算 | 指标计算 | NP、IF、TSS、VI、TRIMP、CP、eFTP、W′ | D14 |
| 业务逻辑层 · 领域计算 | 区间划分与训练分类 | 基于 FTP 的七区划分、依强度因子与时长分类 | D16、D17 |
| 业务逻辑层 · 领域计算 | 功率曲线 | 各时长最佳平均功率，跨活动分别取值再汇总 | D14 |
| 业务逻辑层 · 流程编排 | 计划生成 | 调用云端 LLM 生成训练计划 | D5 |
| 业务逻辑层 · 流程编排 | 计划审核 | 确定性规则校验打底、LLM 复核在上，不合格回炉重生成 | D5、D12 亮点② |
| 业务逻辑层 · 流程编排 | 反馈调整 | 主观反馈与客观功率数据融合，调整后续阶段强度 | D12 亮点③ |
| 表现层 | 数据看板 | 功率曲线、区间分布、十四天负荷趋势等可视化与交互 | D7、D12 亮点① |
| 表现层 | 文件上传与管理 | 上传、导入状态与文件台账 | D6、6.7 |
| 表现层 | 训练计划与反馈 | 计划查看、审核结果展示、主观感受提交 | D5 |
| 横切 | 架构与工程 | 三层依赖自动检查、uv 环境与锁文件、测试结构、一键启动与部署脚本 | D2、D3、D8、D9 |

技术约定沿用项目既有决策：前端 Vue 3 + Element Plus + ECharts，前后端分离；指标计算走本地规则引擎，训练计划生成走云端 LLM API，审核为规则校验加 LLM 复核。

## 三、目录内约定

1. 数据、密钥等不进入本目录跟踪范围；大模型 API Key 必须外置为环境变量，不写入源码或配置文件。
2. 一次性验证脚本与中间产物放本目录下的 `tmp/`，验证完即弃。
3. 涉及项目级决策的改动（表结构、目录结构、层间依赖等），先改 `PROJECT_CONTEXT.md`，再改这里的代码。
